## 2. 衔接契约（给生成侧的设计约束）

1. **idle（待机呼吸休闲）**：首尾帧完全一致、动作轻柔缓慢 → 连续滚动时无缝。
   **实测补充（2026-09-14）**：AI 出片整片 5s 硬接回开头，接缝是自身常规帧间差的 3.5 倍
   （每周期可见一跳）。idle 必须先裁出**无缝循环段**（`tools/find-loop.py`：同时比对接缝处的
   姿势一致性与运动连续性），再上线。
   **定案（2026-09-14）**：循环段 = 母版 `待机呼吸.webm`（152 帧 720×1280）的 **f77..f138**，
   62 帧 @30fps = 2.07s。实测循环接缝 f138→f77 = **2.89**、帧间变化中位 4.82 / 最大 **9.07**
   （640×360 素材口径，见 §9）。**f0 与 f31 仅差 1.22** → 这 62 帧里含两个完全相同的呼吸周期
   （周期 ≈31 帧 / 1.03s），故相位只有 31 个不同取值。
   → **f77 / f138 这两个数从此是契约（见 §2.1）。**
2. **单次动画（clicks / 小动作池 / drag）**：首帧 = 对应姿势，**末帧 ≈ 中立站姿**
   → 播完 `handleEnded` 回链不跳变。这是所有单次动画的统一收尾姿势。
   **实测补充（2026-09-14）**：各片与 idle 是不同批次生成，站位一致但贴图有差，"末帧≈站姿"
   仍会闪。现统一走 `scripts/build-chain.py` 烘焙成 **待机头 4 帧 + 主体 + 待机尾 4 帧**，
   首帧 = idle 循环点 f77、末帧 = f138，两处拼接落在片**内部**（第 4 帧 / 倒数第 5 帧）。
   **修正（2026-09-14 晚）**：曾用 10 帧 premultiplied 溶解修这两处，用户实测**重影比跳变更难看**
   （两张不同的画互溶 = 双重曝光），已改为 `dissolve_frames: 0` **硬切**。
   **硬切实测两处为 18.6~25.2，是 idle 自身最大帧间变化 9.07 的 2~5 倍 —— 仍是可见跳变。**
   烘焙只是把缝搬进片内、不再依赖引擎淡化，**并没有消除它**；素材侧的理论下限见 §2.1。
   顺带把每片头尾的空转切掉（开心那片前 1.9s 角色没动，点击后要等 1.9s 才有反应）。
3. **turn（东张西望）**：末帧 = 首帧左右镜像（朝向相反）。引擎只负责翻转 facing，
   动画内容必须自己"转向"完成，且全程面向镜头（正面素材镜像后仍是正面，天然满足）。
4. **move（悠闲散步）**：首尾各一段原地站立（约 1s），引擎在窗口内平移 sprite 完成位移；
   站立段时长要与 config 的 leadSec/tailSec 对齐（见 §6）。
5. **drag**：拖拽期间保持悬空（循环或长片），释放后引擎回循环 idle。

### 2.1 接缝相位契约（v3 · 2026-09-14 实测定案）

**契约**：所有非 idle 素材

| 项 | 值 |
|---|---|
| 入场（首帧） | 待机母版 **f77** = 循环点 |
| 退场（末帧） | 待机母版 **f138** = 循环末帧 |
| 素材尺寸 | 640×360；角色高 270、脚底 y=330、中心 x=320（母版 720×1280 对应高 ≈787、脚底 y≈1009、中心 x≈356） |
| 帧率 | 30fps（与 idle 一致，避免 24→30 帧复制带来的顿挫） |

母版里 f138→f77 本来就是无缝的（2.89）。首末帧落在循环点上后，前后接待机都是**循环内的自然延续**，
不需要任何过渡素材。

**拓扑前提**：引擎正常路径是**星形** —— `handleEnded()` 的四个分支（事件 / turn / drag+clicks / 其余）
**一律回 idle**，不存在"动作直接接动作"的正常边。所以一切经 idle 中转时，
**只需要一套待机基准，动作之间不需要互相对齐。**

**唯一例外**：`onClick()` **不判断当前在播什么**，直接 `playOnce(随机 clicks)`。
在吃东西/睡觉时点一下 = **动作→动作的跨代直连**（240ms 淡化 = 两张不同的画互溶 = 重影）。
这条边素材侧解决不了，归引擎侧（见 §3.6）。

**待机的单点代价**：待机自己一动（换循环点、改姿势、换服装），**所有动作的书挡同时失效、整批重做**。
待机从"一个素材"变成单点依赖，动画条数越多代价越重。

**生成路线（用户定案 2026-09-14）**：一条一次生成 **待机 + 动作主体 + 待机**，
素材侧再扫相位、双向裁剪到 f77 / f138、量边界残差。理由是它把两处内部硬切搬进同一次生成，
让边界两端变成**同一代的画**（只剩呼吸相位差），而不是两次独立生成的重绘。

**为什么不走首尾帧路线**：Ark `doubao-seedance-2-0-mini-260615` 的首尾帧模式两端是原样吐回
（实测 `f000 vs 给定首帧 = 9.3` = 编码噪声，衔接确实归零），**但主体动作被重画** ——
吃干饭的碗在 f10→f11 之间凭空出现、睡觉的瘫倒偏快。两条路线是取舍：
**首尾帧买"接缝精确"，待机+主体+待机买"动作忠实"。**

**精灵图 / 帧动画路线：不采用（用户分析定案 2026-09-14）。** 实测理由：
838 帧转图集 = PNG 44MB（**13.6×**）/ WebP 无损 30MB（9.5×）/ WebP q90 13.6MB（**4.2×**）
（现 webm 合计 3.2MB）；解成 RGBA 常驻约 **218MB**，需自写 LRU 淘汰；渲染层要从 `<video>`+CSS
重写成 canvas，会碰到已修好的缩小/闪烁两个 bug。**且它不解决根本问题** —— 跨代重绘在精灵图里一模一样存在。
- 备选留档：若将来确实需要更强的过渡控制力，**保持 VP9-alpha 素材不变、把 CSS opacity 换成
  `<canvas>` + `drawImage(video)`** 即可拿到帧级合成控制，素材成本为 0。
- 唯一能从根上消掉"同一个姿势被画两遍"的是**分层绑定**（前提：原始素材有分层 PSD / Live2D 模型）。

## 3. 交互状态机（引擎实现，审计确认）

```
启动 → playIdle()
       │
       ▼
playIdle(): rollKind(权重) ──► idle(35%) → playOnce(idle)
       │                        turn(5%)  → playOnce(turn) → 播完翻 facing → playIdle
       │                        move(20%) → tryMove() 平移 → 播完 → playIdle
       │                        小动作池(40%) → playOnce(小动作) → 播完 → playIdle
       ▼
   单次动画播完 → handleEnded()
       ├─ 事件动画 → 直接回 idle（不进随机链）
       ├─ turn     → 翻 facing → playIdle
       ├─ drag/clicks → 回 idle
       └─ 其他(move/小动作) → playIdle

用户交互：
  ├─ 点按      → playOnce(随机 clicks) → 播完回链
  ├─ 拖拽      → 超过阈值 → playOnce(随机 drag) 悬空；释放 → 循环 idle（落定）
  ├─ 右键菜单  → 点播任意动画；移动动画走真实平移
  └─ 事件(balance/whisper/workStatus) → 播对应池动画 → 回 idle（当前功能关闭）
```

**关键机制（审计发现）**：idle 也是"单次播放 + 链式重滚"，不是真无限循环。
idle 素材因此必须无缝（首尾一致），否则每次滚回 idle 都跳变。

## 3.5 风格组：按组切换（正面 / 3-4）

> 2026-09 新增（引擎已实现，见 `runtime/electron-helper/renderer.js` 的 `isInStyle / stylePool / switchStyle`）。
> 目的：正面与 3/4 侧面两套素材**不混池**（避免随机跳风格），用"风格切换转身"动画驱动整组切换。

**配置字段**（`animations` 内）：
- `groups`：`{ 组名: [动画名...] }`。未登记到任何组的动画 = **通用**（两组都可用）。
- `initialStyle`：启动时所在组。
- `styleTurnChance`：每次 `turn` 触发"风格切换转身"的概率（默认 0.2）。
- `styleTurns`：`{ 当前组: [切换转身动画名] }`，动画播完引擎把 `currentStyle` 切到另一组。

**行为**：
- 随机链（idle/clicks/drag/moves/categories）只从 `currentStyle` 对应组取动画；组内缺槽位时该槽位降级（如正面组无小动作 → 小动作槽跳过，兜底 idle）。
- `turn` 分流：概率 `styleTurnChance` 选 `styleTurns[当前组]`（播完**换组 + 翻 facing**），否则选普通 `turn`（同组内只翻 facing）。
- 切换后，后续所有动画来自新组 → 风格被转身动作自然过渡，不跳变。

**两种转向的分工**（用户定义，2026-09）：

| 转向类型 | 走哪条通道 | 动画 | 引擎行为 |
|---|---|---|---|
| **左转右**（同风格内翻朝向） | `turn` 池 | 东张西望（3-4 档） | 只翻 `facing`（CSS 镜像），**不换档** |
| **左侧面→正面**（换风格档） | `styleTurns["3-4"]` | 转身 | 播完切到**正面档** + 翻 `facing` |

**当前接线**：`turn: ["左侧面-东张西望"]`；`styleTurns: { "3-4": ["转身"], "正面": [] }`。
实测（真实配置模拟 4000 次）：3-4 档转身 = 东张西望 79.5% / 转身 20.5%；正面档无转身素材 → 降级为待机（100%，不崩）。

**当前分组**：正面 = [正面-待机呼吸休闲4, 正面-悠闲散步]；3-4 = 全部 左侧面-*。
**待办**：
1. **反向片**（正面→左侧面）做好后填 `styleTurns["正面"]`，才能从正面档切回；
2. 正面档还需补：普通转身（正面版东张西望）、点击回应、小动作——补齐后正面档才可完整交互。

## 3.6 衔接引擎 v2.1（2026-09 实装，renderer.js）

跳变根因排查结论：素材接缝未达契约（见 `assets-custom/QA-NOTES.md` 实测表）是主因，
引擎侧五处放大器已修：

1. **加载空窗**：旧实现 `ended` 后才发 fetch 下一段，旧画面冻结在末帧等「网络+解码」。
   → 现启动即后台**预取全部动画为 blob URL**（`prefetchAssets`），切换零网络等待。
2. **旧画面早停**：旧实现淡化开始瞬间即 `pause()` 旧视频（淡化期叠定格帧）。
   → 现旧视频**播完整个交叉淡化再停**（CROSSFADE_MS=240 与 CSS 同步）。
3. **首帧未上屏即翻台**：`loadeddata` 只保证首帧解码完成。
   → 现等 `requestVideoFrameCallback` 首帧**呈现**后再翻 opacity（双 rAF 兜底 + 400ms 超时兜底）。
4. **idle 自滚整片重载**：占 35% 权重的 idle 每次滚回都冻结+闪。
   → 同源续播 fast path：目标=前台当前动画时**原地 seek 回 0**（不换缓冲不加载不淡化；
   移动动画按 currentTime 驱动窗口平移，守卫跳过此路径）。
5. **两层同时淡化 → 覆盖度凹陷（2026-09-14）**：新画面淡入的同时旧画面淡出，两层各自半透明
   叠加的合成覆盖度 = 1-(1-a旧)(1-a新) = 1-t+t²（t=0.5 时 0.75）→ 背景从缝里透出来，
   表现是"换片时整只闪一下"（白底片尤其明显）。
   → 现**两段式淡化**：旧画面保持全不透明直到新画面淡入满，再在其之上淡出；全程至少一层不透明。
   同时 z-index 固定新层在上、Q 弹挤压两层一起压且锚在 `FEET_Y` 脚底线。
   冒烟自检 `crossfadeCoverage` 守住这条不变量（要求最小覆盖度 ≥0.99，实测 1.0）。

淡化 0.18s→0.24s ease-in-out。**注意**：以上只消灭"引擎放大器"，
素材接缝（idle 首尾闭合度、单次动画收尾站姿）仍须按 §2 契约回炉，
验收跑 `python tools/check-seams.py`（<3 无感 / 3~8 轻微 / >8 跳变）。

**淡化时长应按「边的性质」取，不该是一个常数（2026-09-14 实测定案）**：
现在 `CROSSFADE_MS = 240` 对所有边一视同仁，但两类边的性质完全不同 ——

| 边 | 性质 | 该用什么 | 为什么 |
|---|---|---|---|
| **书挡边**（idle ↔ 动作，走 §2.1 契约） | 同代，只有呼吸相位差 | **长**淡化（240ms 甚至更长） | 同代不同相位的淡化读起来是**角色在动**（morph），长淡化把 20 的相位差铺成平滑位移 |
| **中断边**（动作 ↔ 动作，`onClick` 直连） | 跨代，两张不同的画 | **短**淡化（~100ms）+ Q 弹 | 跨代淡化 = 双重曝光（重影），淡化时长就是重影时长，线性放大 |

**Q 弹遮盖的实测覆盖范围**：`squashScale(u, .55)` / `SQ_DURATION_MS=220` 的强形变窗口是
**0~122ms**（99ms 压到 55%，122ms 回到 70%），而淡化是 240ms ——
**122~240ms 这 118ms 重影是裸的**，这就是中断边唯一需要修的地方。
把这一条边的 `CROSSFADE_MS` 降到 ~100ms 比加深 Q 弹更干净。

**特效遮盖的硬判据**：特效能"修饰"接缝，当且仅当它做到三件事之一 ——
**形变到看不清姿势 / 完全遮住 / 抹掉细节**。星点、光晕、小烟雾这类装饰性特效应**叠在重影上面**，
不解决问题。**不要用闪白**（本项目已专门修过换片闪烁，见本节第 5 条）。
**特效不能修的东西**：两端差异大到连 Q 弹都压不住时（同一姿势被画成两个角色），任何特效都是徒劳。

**选项（比特效干净）**：让中断**先经待机** —— 把"动作→动作"一条边拆成两条 idle↔动作边，
而这两条本来就是无缝的，Q 弹即可退化为纯手感，上述 118ms 缺口随之消失。

## 4. 朝向与镜像

- 默认面向左（`facing='left'`）；朝右时 CSS `scaleX(-1)` 镜像。
- **正面素材镜像无感**（正面左右对称），故 12 制全部正面即可，无需 noMirror 分类。
- turn 播完立即翻 facing；随后的移动方向跟随 facing。

## 5. 权重配置（守恒 100）

```
idle 35 + turn 5 + move 20 + 小动作池 40 = 100
```
- `rollKind` 语义：P(idle)=0.35 / P(turn)=0.05 / P(move)=0.20 / P(小动作)=0.40
- **小动作池总权重必须 = 100 − idle − turn − move**（rollKind 的余量即小动作概率）。
- 小动作池内部：`pickWeightedCategory` 按 category.weight 加权，池内动作等概率随机（排除当前）。

## 7. 引擎硬性约束（交互逻辑核查结论）

- `events.*` 数组**必须非空**（引擎校验要求）；workStatus 池长度 **≥6**（引擎第 1240 行硬要求）。
- 小动作池 category 的 `weight` 必须与权重表守恒（见 §5）。
- move 动画必须配 leadSec/tailSec；`travelWindow = max(0.1, duration − leadSec − tailSec)`。
- turn 动画引擎只翻 facing，不负责内容——动画必须自带"转向"。
- 拖拽动画要在 dragState.active 期间持续悬空；释放才回 idle。
- 正面素材无 noMirror 需求；若未来加入带文字/方向敏感动画，须配 `noMirror:true` 分类。

## 9. 实测基线与量测方法（2026-09-14）

> **口径**：一律 **640×360 素材口径**，且**只在角色像素上算**（两帧前景并集上取 `mean(|Δ|)`）。
> 跨口径（720×1280 母版 vs 640×360 素材）的数**不可直接比** —— 上采样会改变统计量。

### 9.1 基线表

| 量 | 数值 | 含义 |
|---|---|---|
| idle 自身帧间变化 | 中位 4.82 / p95 7.56 / **最大 9.07** | "正常动画"的步进上限 |
| idle 循环接缝 f138→f77 | **2.89** | 无缝循环的水平 |
| idle f0 vs f31 | **1.22** | 循环段含两个完全相同的呼吸周期 |
| **相位错配** idle(φ) vs idle(f77) | 中位 **19.83** / p95 28.47 / **最大 28.94** | 见 §9.3 —— 素材侧消不掉的天花板 |
| **跨代错配** 原片动作站姿 vs idle | **19.4 / 20.2 / 20.6 / 25.9** | 两次独立生成的重绘差 |
| 线上硬切实测（头→主体 / 主体→尾） | 开心 19.8/19.7 · 生气 18.6/18.8 · 吃干饭 19.7/19.0 · 睡觉 22.8/25.2 | 与跨代错配吻合（两个独立量测互证） |
| 主体内部最大步进 | 开心 29.1 · 生气 44.3 · 吃干饭 46.4 · 睡觉 66.8 | 出现在高速段（坐下/瘫倒），**不是接缝** |

**一个反直觉的结论**：跨代错配（19~26）和相位错配（19.8/28.9）**是同一个量级**。
所以"以待机为基准"这条路线的收益**不是把 20 降到 3**（数值上降不动），
而是改变错配的**性质** —— 从"两张不同的画"（淡化 = 重影）变成"同一张画的两个呼吸相位"
（淡化 = 平滑位移）。定性收益为真，定量收益不存在。

### 9.2 正确的量尺

**只算角色像素的逐帧步进。** 不要在全画幅上算：透明/绿底占 70%，会把数值稀释掉一半以上，
也会掩盖真实跳变。

### 9.3 三个量测陷阱（全部踩过）

1. **不要按包围盒中心对齐后再比。** 尾巴一摆包围盒中心就偏几十像素，对齐等于把图平移了再比原图，
   量到的是自己的平移误差。曾因此读出"出口 32.6"，真值是 9.4（编码噪声）。
   → **标定方法：同一张图自己比自己，误差必须是 0。**
2. **「对齐后残差」不能用来区分"整体位移"和"细节冲突"。** 实测同代相位对与跨代对在 ±12px 内
   最优对齐后都只降 0~1% —— 两边都不是刚性位移，区分不了。**别用这个判据。**
3. **条件帧比对必须同尺寸、同背景。** 条件帧是绿幕图，idle 是 alpha 合成到绿，背景本身就差几十 RMS。
   曾因此把跨代错配误报成 80~95，真值是 19~26。

### 9.4 验收判据（裁剪之后量什么）

| 项 | 合格 |
|---|---|
| 边界**原始差**（同尺寸直接比，**不做任何缩放**） | **编码噪声量级：个位数** |
| 若停在 19~26 | 说明模型**没照抄待机、而是又重画了一版** → 这条生成作废 |
| 裁到书挡后的首/末帧 vs idle f77 / f138 | 同上（个位数） |
| 片内主体最坏步进 | 允许高于 9.07（那是真实高速动作），但须确认出现在动作过程中、**不在接缝处** |

**边界原始差是唯一一个"一个数就能分辨成败"的指标** —— 它直接回答"模型是抄还是画"。
这条是每次交接素材时**第一件要做的事**。

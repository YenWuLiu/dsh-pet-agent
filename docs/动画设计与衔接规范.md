# 引擎行为与衔接规范

> 本文只讲**引擎怎么播**（渲染端硬行为）与**素材必须满足的衔接契约**。
> 素材清单、规格契约与生产流程见 [`assets/README.md`](../assets/README.md)；
> 生成提示词见 [`动画生成清单.md`](动画生成清单.md)。
>
> 引擎实现：`runtime/electron-helper/renderer.js` 与 `shared-core.js`
>（后者是 `shell/` 的构建产物，见 `NOTICE.md`）。

## 1. 交互状态机

```
启动 → playIdle()
       │
       ▼
playIdle(): rollKind(权重) ──► idle    → playOnce(idle)
       │                        turn    → playOnce(turn) → 播完翻 facing → playIdle
       │                        move    → tryMove() 平移 → 播完 → playIdle
       │                        分类池   → playOnce(分类动作) → 播完 → playIdle
       ▼
   单次动画播完 → handleEnded()
       ├─ 事件动画(events.*) → 回 idle（不进随机链）
       ├─ turn              → 翻 facing → playIdle
       ├─ drag / clicks     → 回 idle
       └─ 其他(move/分类)    → playIdle

用户交互：
  ├─ 点按      → playOnce(随机 clicks) → 播完回链
  ├─ 拖拽      → 超过阈值 → playOnce(随机 drag) 悬空；释放 → 循环 idle
  ├─ 右键菜单  → 点播任意动画（移动动画走真实平移）
  └─ 事件(balance / whisper / workStatus) → 播对应池动画 → 回 idle
```

**关键机制**：idle 也是"单次播放 + 链式重滚"，不是真无限循环 ——
所以 idle 素材**必须首尾一致**，否则每次滚回 idle 都跳变。

## 2. 衔接契约（素材必须满足）

| 槽位 | 硬性要求 | 为什么 |
|---|---|---|
| `idle` | **首尾帧一致**（无缝） | 见上：idle 是链式重滚 |
| `turn` | **末帧 = 首帧的左右镜像** | 引擎播完只负责翻 `facing`，转向得由动画自己完成 |
| `clicks` / 分类 / `drag` | **末帧 ≈ 中立站姿** | 播完回 idle 才不生硬 |
| `moves` | **首尾各一段原地站立**，实测后回填 `leadSec`/`tailSec` | 引擎在窗口内平移精灵完成位移 |
| `drag` | 拖拽期间持续悬空 | 释放才回 idle |

## 3. 风格组：按组切换（正面 / 3-4）

> 引擎已实现（`renderer.js` 的 `isInStyle / stylePool / switchStyle`）。
> 目的：两套素材**不混池**（避免随机跳风格），用"风格切换转身"动画驱动整组切换。
> **本项目当前只有正面一套，配置里没有 `groups` / `styleTurns`，以下字段尚未接线。**

`animations` 内可用字段：

- `groups`：`{ 组名: [动画名...] }`。**未登记到任何组的动画 = 通用**（各组都可用）。
- `initialStyle`：启动时所在组。
- `styleTurnChance`：每次 `turn` 触发"风格切换转身"的概率（默认 0.2）。
- `styleTurns`：`{ 当前组: [切换转身动画名] }`，动画播完引擎把 `currentStyle` 切到另一组。

行为：

- 随机链（idle / clicks / drag / moves / categories）只从 `currentStyle` 对应组取动画；
  组内缺槽位时该槽位降级（如某组无分类动作 → 该槽跳过，兜底 idle）。
- `turn` 分流：按 `styleTurnChance` 选 `styleTurns[当前组]`（播完**换组 + 翻 facing**），
  否则选普通 `turn`（同组内只翻 facing）。

两种转向的分工：

| 转向类型 | 走哪条通道 | 引擎行为 |
|---|---|---|
| **同风格内翻朝向** | `turn` 池 | 只翻 `facing`（CSS 镜像），**不换组** |
| **换风格档** | `styleTurns[当前组]` | 播完切到另一组 + 翻 `facing` |

## 4. 衔接引擎的实现细节（renderer.js）

跳变根因排查结论：**素材接缝未达契约是主因**，引擎侧五处放大器已修：

1. **加载空窗**：旧实现 `ended` 后才 fetch 下一段，旧画面冻结在末帧等"网络+解码"。
   → 现启动即后台**预取全部动画为 blob URL**（`prefetchAssets`），切换零网络等待。
2. **旧画面早停**：旧实现淡化开始瞬间即 `pause()` 旧视频（淡化期叠定格帧）。
   → 现旧视频**播完整个交叉淡化再停**（`CROSSFADE_MS=240` 与 CSS 同步）。
3. **首帧未上屏即翻台**：`loadeddata` 只保证首帧解码完成。
   → 现等 `requestVideoFrameCallback` 首帧**呈现**后再翻 opacity（双 rAF + 400ms 超时兜底）。
4. **idle 自滚整片重载**：占大权重的 idle 每次滚回都冻结+闪。
   → 同源续播 fast path：目标 = 前台当前动画时**原地 seek 回 0**（不换缓冲不加载不淡化；
   移动动画按 `currentTime` 驱动窗口平移，守卫跳过此路径）。
5. **两层同时淡化 → 覆盖度凹陷**：新画面淡入的同时旧画面淡出，两层各自半透明叠加的
   合成覆盖度 = `1-(1-a旧)(1-a新) = 1-t+t²`（t=0.5 时 0.75）→ 背景从缝里透出来，
   表现是"换片时整只闪一下"（白底片尤其明显）。
   → 现**两段式淡化**：旧画面保持全不透明直到新画面淡入满，再在其之上淡出；全程至少一层不透明。
   同时 z-index 固定新层在上、Q 弹挤压两层一起压且锚在 `FEET_Y` 脚底线。
   冒烟自检 `crossfadeCoverage` 守住这条不变量（要求最小覆盖度 ≥0.99，实测 1.0）。

淡化 0.18s → 0.24s ease-in-out。**以上只消灭"引擎放大器"**，素材接缝仍须按 §2 契约做。

**淡化时长应按「边的性质」取，不该是一个常数**：

| 边 | 性质 | 该用什么 | 为什么 |
|---|---|---|---|
| **书挡边**（idle ↔ 动作） | 同代，只有呼吸相位差 | **长**淡化（240ms 或更长） | 同代不同相位的淡化读起来是**角色在动**，长淡化把相位差铺成平滑位移 |
| **中断边**（动作 ↔ 动作，`onClick` 直连） | 跨代，两张不同的画 | **短**淡化（~100ms）+ Q 弹 | 跨代淡化 = 双重曝光（重影），淡化时长就是重影时长 |

**Q 弹遮盖的实测覆盖范围**：`squashScale(u, .55)` / `SQ_DURATION_MS=220` 的强形变窗口是
**0~122ms**，而淡化是 240ms —— **122~240ms 这 118ms 重影是裸的**，这是中断边唯一需要修的地方。
把这条边的 `CROSSFADE_MS` 降到 ~100ms 比加深 Q 弹更干净。

**特效遮盖的硬判据**：特效能"修饰"接缝，当且仅当它做到三件事之一 ——
**形变到看不清姿势 / 完全遮住 / 抹掉细节**。星点、光晕、小烟雾这类装饰性特效应**叠在重影上面**，
不解决问题。**不要用闪白**（本项目已专门修过换片闪烁，见上第 5 条）。

**选项（比特效干净）**：让中断**先经待机** —— 把"动作→动作"一条边拆成两条 idle↔动作边，
这两条本来就是无缝的，Q 弹即可退化为纯手感，上述 118ms 缺口随之消失。

## 5. 朝向与镜像

- 默认面向左（`facing='left'`）；朝右时 CSS `scaleX(-1)` **镜像整个精灵层**。
- `turn` 播完立即翻 `facing`；随后的移动方向跟随 `facing`。
- **正面素材镜像基本无感**，但**带文字 / 方向敏感的画面会被镜像成反的** →
  这类动画必须放进 `categories[].noMirror: true` 的分类里。引擎两条路径都认这个标记：
  随机链的 `pickWeightedCategory` 会跳过该分类，右键点播由 `isNoMirrorAnimation`
  把 `facing` 复位成 left。
- ⚠ **`events.*` 不受这个机制保护** —— 事件动画没有 noMirror 过滤，
  带文字/符号的事件动画在 `facing='right'` 时会以镜像形态出现。

## 6. 权重配置（守恒 100）

- `rollKind` 按 `animationWeights` 的 `idle` / `turn` / `move` 掷点：
  P(idle) / P(turn) / P(move) / P(分类池) = `idle` / `turn` / `move` / `(100 − 三者之和)`。
- **各分类 weight 合计必须 = 100 − idle − turn − move**（rollKind 的余量即分类池概率）。
- 分类池内部：`pickWeightedCategory` 按 `category.weight` 加权，池内动作等概率随机（排除当前）。
- 三者之和必须 < 100，否则没有分类池的余量。

## 7. 引擎硬性约束（核查结论）

- `idle` **必须非空**；`turn` / `drag` / `clicks` 必须存在，**可为空数组** ——
  空池都安全：转向档位落回分类池、拖拽只走物理跟手、点按只做 Q 弹挤压。
- `moves` 必须有 `default` 对象与 `actions` 数组；`actions` 为空 → `tryMove()` 返回 false，落回分类池。
- `events.*` 的每个值必须是非空字符串数组，**段本身可以是空对象**；
  `workStatus` 池长度必须 **≥6**（引擎硬要求，不足 6 整条静默不生效），
  且索引必须与渲染端硬编码的
  `{thinking:0, working:1, result:2, waiting:3, success:4, error:5}` 严格同序。
- `moves` 的 `travelWindow = max(0.1, duration − leadSec − tailSec)`。
- 宿主校验（`src/vendor/config.ts` 的 `animationsValid`）**只作用于覆盖层**
  （`main-config.json` / `pet/<名>-config.json`）；内置默认配置 `assets/config.jsonc` 不走校验。
  但覆盖层若自己写 `animations`，仍要求 `events.balance` 非空。

## 8. 量测方法与三个陷阱

**口径**：一律 **640×360 素材口径**，且**只在角色像素上算**（两帧前景并集上取 `mean(|Δ|)`）。
跨口径（母版 vs 素材）的数**不可直接比** —— 上采样会改变统计量。
**不要在全画幅上算**：透明区占 70%，会把数值稀释一半以上，也会掩盖真实跳变。

1. **不要按包围盒中心对齐后再比。** 尾巴一摆包围盒中心就偏几十像素，对齐等于把图平移了再比原图，
   量到的是自己的平移误差。
   → **标定方法：同一张图自己比自己，误差必须是 0。**
2. **「对齐后残差」不能区分"整体位移"和"细节冲突"。** 实测同代相位对与跨代对在 ±12px 内
   最优对齐后都只降 0~1% —— 两边都不是刚性位移，区分不了。**别用这个判据。**
3. **比对必须同尺寸、同背景。** 绿幕条件帧 vs alpha 合成到绿的 idle，背景本身就差几十 RMS。

**量角色只认最大连通块**：即梦出片带的「AI生成」水印与角色是**两个独立不透明块**，
按整体 alpha 包围盒会量成"头顶→水印底"，于是缩放把角色压小、脚底悬空（2026-09 实测事故）。
`scripts/check-anchor.py` 与 `scripts/normalize-webm.py` 都按这个口径量角色。

**但裁剪窗相反，要用全部内容**：有些片故意带与角色**不连通**的气泡/道具/特效
（对话气泡、三球、笛子、蝴蝶蜜蜂、鲸鱼虚影），只按角色 bbox 裁会把它们切掉。
`normalize-webm.py` 因此分成两套 bbox：**角色 bbox（最大连通块）→ 缩放与锚点；
全部内容 bbox（所有 alpha>40 像素）→ 裁剪窗**。
